# Reference Image Kernel

Turn a retained PNG into a constrained image-edit job without collapsing generation, review, acceptance, save, export, promotion, or publication.

## Routing

- Use the built-in ImageGen tool as the canonical interactive executor. Pass every local source through its actual `referenced_image_paths`; a filename, board item ID, or prose description is not an attachment.
- Use `openai-image-api-cli` for explicitly requested API/CLI execution when a governed run needs model, output, and no-overwrite receipts. Repeated interactive generations still use the built-in tool. The bundled ImageGen CLI is a separate fallback, not this receipt adapter.
- Use Template Creator to package a reusable personal image template. Keep its generated `artifact-template.json` version 1 unchanged and add `image-template.json` as a companion skill-owned profile.
- Never modify a bundled or remote plugin cache. Extract useful contracts into an owned skill or repair the package through a supported update path.

## Authority boundaries

- A reference image is immutable input unless the user explicitly replaces the template.
- Generation produces candidates only.
- Structural validation and visual review do not imply human acceptance.
- Human acceptance does not imply native save, export, registration, promotion, upload, publication, deployment, or licensing.
- Preserve immutable batch contracts and completed-run evidence as historical authority.

When supplying an immutable batch's generator role, use that owner's paths and stop boundary.
Return control before visual review, iteration or acceptance; this skill's standalone steps do not
expand the batch role. A textual description cannot satisfy `actualReferenceRequired: true`.
If a required reference cannot be attached, report the unsatisfied input and preserve the contract.

## Required package

A reusable template package contains:

- `artifact-template.json` generated by Template Creator.
- `assets/reference.png`, retained unchanged.
- `assets/preview.png`, visually inspected and representative.
- `image-template.json`, validated against `references/image-template-v1.schema.json`.

The companion profile records only observable or user-supplied facts. Leave uncertain properties in `profile.unknowns`; do not infer brand rules or production requirements from appearance alone.

## Reference roles

For every source, assign one explicit role:

- `template`: overall visual system and layout.
- `composition`: framing, hierarchy, spacing, or safe zones.
- `identity`: subject identity, silhouette, proportions, or product geometry.
- `style`: medium, finish, mark-making, or rendering treatment.
- `palette-material`: colors, surfaces, and material response.
- `lighting`: light direction, contrast, atmosphere, and shadow behavior.
- `typography`: type hierarchy and placement; exact copy still belongs in a deterministic layer.

When several references are used for a job, label them by index and role in the prompt. State which reference wins if their constraints conflict.

## Workflow

1. Inspect the retained reference and preview. Stop on blank, clipped, corrupted, or nonrepresentative media.
2. Load the bundled workspace dependency runtime. Use its Python executable for the validator; do not assume system Pillow or Pydantic packages exist.
3. Validate the package before generation:

```bash
"$PYTHON_BIN" "$SKILL_DIR/scripts/validate_template.py" \
  --package "/absolute/path/artifact-template-example"
```

4. Compile the job in this order:
   - Intended use and requested change.
   - Indexed references and roles.
   - Composition, subject, materials, lighting, palette, and typography.
   - `mustKeep` invariants.
   - `allowedChanges`, including filled slots.
   - `mustAvoid` constraints.
   - Exact output geometry and safe zones.
5. Pass the real reference paths to the built-in ImageGen edit route. Default to one candidate; create more only when the user asks or comparison materially helps.
6. Inspect each output structurally and visually. A structural pass does not assess depiction or usefulness. Iterate with one targeted change while restating all invariants, within the owning workflow's role.
7. Emit a `TemplateImageRunReceiptV1` using `references/template-image-run-receipt-v1.schema.json` and follow [receipt validation](references/receipt-validation.md). Cover every structural/visual gate and exact layer in the pinned profile; retain pending checks and explain non-applicability. Record source, profile, prompt, and output digests plus executor/model, validation results, lineage, and actual recorded authority states. If the built-in executor does not disclose its model, use `not-exposed-by-executor`; do not infer a model from a CLI default. An audit candidate retained for evidence is not a final asset save or acceptance.
8. Stop for human acceptance. Do not promote or publish the selected candidate automatically.

## Exact content

Treat logos, legal text, data, and other exact copy as deterministic layers whenever fidelity matters. The image model may create the visual base and reserved zones, but the receipt must mark exact-layer verification as pending until the deterministic composition is checked.

## Validation requirements

- Full PNG decode for reference and preview.
- Reference SHA-256 and dimensions match the profile.
- All package-relative paths remain inside the package.
- `match-reference` target dimensions equal the retained reference. Use
  `match-aspect` when an executor returns a standard larger raster with the same
  aspect ratio and exact export sizing remains a later deterministic gate.
- A transparent output requires an alpha channel and at least one genuinely nonopaque pixel.
  Its source may be opaque: target requirements do not apply to the retained input.
- Slot identifiers are unique and every `slot:<id>` allowed change resolves.
- Structural and visual gate lists contain the required checks.
- Receipt writes are no-overwrite by default.
- Human acceptance is always required.
- Candidate inspection leaves generation `not-established`; only an execution record can supply
  that claim. Receipt integrity and check coverage are separate from the returned assessment.
  Recorded execution and acceptance fields are not independently verified by the validator.

## Constraints

- Do not store a moving model default in `image-template.json`; resolve current capabilities at execution time and record the resolved model in the run receipt.
- Do not claim generated pixels are deterministic. Request compilation and exact overlay composition may be reproducible; model output is a candidate.
- Do not replace a template, change its digest, or overwrite a receipt silently.
- Do not ask an image model to reproduce exact multilingual or legal copy when a deterministic overlay is available.
